# Native device acceptance — development candidate only

Do not install or run against real rewards until the user chooses to begin this device check. No live claim, CAPTCHA bypass, cache migration or destructive action is authorized. Use a separate Chrome profile where practical; never run v15 and candidate concurrently or switch generations with an unresolved attempt.

1. **Package:** obtain exact CI development artifact; open install.html locally, verify SHA256SUMS.txt and build.json commit/channel/version and asset names. Extract the versioned extension ZIP into a new dedicated folder. Preserve original v15 bookmark, original listener and private backup separately.
2. **Toolbar:** Load unpacked in chrome://extensions; confirm original icon, only expected permissions, direct native side-panel opening, no ERR_FILE_NOT_FOUND. Open/close, pin, switch tabs, reload browser; unrelated tab remains disconnected. Do not initiate a claim.
3. **Saved bookmark:** create an actual Chrome bookmark using the exact javascript: URL from the versioned bookmarklet .txt asset (not console/evaluate); verify the saved URL is intact, including length. On an authorized read-only supported page, check open/close/reinvoke, native page controls usable, no unexpected mutation. Record CSP/length failures; never bypass site restrictions.
4. **Workspace:** keyboard Tab/Shift+Tab/Enter, visible unobscured focus, screen-reader names/status, light/dark, narrow 320/360/400/480 CSS px where possible, browser 200% zoom. Check draft paste and preview with synthetic text only, no queue writes on a live page; switching tabs invalidates context.
5. **Privacy:** if existing saved data is available and user consents, masked reward/history, explicit one-row reveal, expiry/hide/close/tab-switch, explicit local export; keep credentials private. No screenshots containing credentials. Diagnostics opt-in/off, explicit capture of current recognized wizard, structural export with snapshot/event timeline and existing retention preserved; confirm no recording while disabled and no capture on unsupported tab. Compare useful coverage with the original listener; never share raw private files.
6. **Rollback:** stop candidate and remove/disable unpacked extension without clearing site data; do not invoke legacy if unresolved. Preserve old listener diagnostics; confirm original saved bookmark and hosted v15 baseline remain unchanged. Record build hash, Chrome/ChromeOS version, date, each pass/fail/not-run and sanitized error only.

Separate E4 ordinary legitimate live acceptance requires specific user authorization and authentic evidence. This checklist is not a release approval. If a step requires a live mutation or an unresolved state is present, stop and report.

## Optional M1 public catalog acceptance (independent of redemption)
Use the exact verified development package in a separate profile, only when the user elects to begin. Open Campaigns and confirm no automatic public request. If the directory is legitimately accessible and no existing stopped state applies, perform one ordinary manual directory refresh. Record only build SHA, date, outcome, public origin/slug count and whether displayed identities match the permitted official directory. Verify source/freshness labels, unknown terms/stock/compatibility, and persistence after closing/reopening the panel; do not perform additional requests merely to induce failures. On access denial, challenge, rate limit or interrupted/unverified state, stop that retrieval path; do not clear/reset storage, change retrieval route or force a retry. Record the sanitized outcome. No redemption, private cache inspection or new host permission required for this check. Native success establishes directory/manual transport compatibility only; monitoring and core redemption acceptance remain separate.
