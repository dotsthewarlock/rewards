# Development records — compact handoff contract
Historical evidence, not current policy. AGENTS.md and companion/README.md govern. Git diff is change detail; CI is test detail. One compact record per coherent accepted milestone, material decision/blocker, writer transfer or necessary session continuation; append to existing module record where useful. No notes for routine internal iterations, repeated roadmap, transcript or duplicate audit. Prefer brief evidence links over prose; no minimum length. Never include credentials, raw private diagnostics or personal data.

## Record format
- Base → implementation SHA (branch); relevant diff paths/symbols; milestone/scope completed vs remaining.
- Evidence: command/environment as needed, CI link, actual pass/fail/blocked/not run, important limitations. Distinguish synthetic/native/live. Link fixture provenance if changed.
- Material decisions/assumptions only: choice + why/alternative or trade-off + affected contract + evidence/confidence + unresolved risk/revisit trigger. Include meaningful prevention vs recovery choices, compatibility/UX deviations and authorization boundaries. No inference that an assumption is approved.
- Next: highest-priority action, genuine blockers, minimum user action (or none), release/rollback status if changed. For actual milestone closure or interrupted continuation give status, exact tested SHA and CI, saved record link and writer disposition. Verify remote save; module streams do not edit shared README. Only if routing to another conversation is necessary, supply short copyable handoff with role/ref/status and links; full sanitized fallback if persistence fails. No re-upload, progress relay or new handoff for routine internal checkpoints.
- Review: author self-check and applicable automated evidence for routine reversible work; receiving architect verifies refs/scope and outcome without duplicating accepted evidence. Independent targeted review of material high-risk changes or gaps; bounded periodic audit at coherent roadmap/release milestones or triggered by drift/regression. Record verified/needs correction/deferred only where material. Update shared policy/status only when changed. Unchanged test inputs in record-only successors can reuse exact implementation evidence, not claim a fresh run; preserve applicable release-specific exact-HEAD and hosted checks.
