# UX design specification — Material Design 3 (R3)
2026-11-27 | Governing UX specification. Supersedes earlier UX contracts, standalone 07 and alternative mockups. User approved the revised UX-first recommendation; concepts still need validation.

## Mandate and audit
M3 is authoritative design foundation, adapted for a high-frequency utility. Preserve capabilities, data compatibility and transaction safeguards, not visual or interaction implementation. Optimize predictable, efficient redemption with low cognitive load. Source-based heuristic audit (not usability study): v15 460px fixed overlay obstructs merchant content; 10–12px type, 27–34px controls, translucent contrast, footer counters and drawers obscure essentials; technical slugs, prominent Clear Cache, overlapping Start/Resume and Auto-Redeem, persistent email/clipboard settings, technical statuses and color-only dots. Diagnostic listener popup mixes settings, counters, export, capture and destructive actions. Two extensions duplicate entry points. Preserve useful functionality, remove friction.

## Selected direction
Native Chrome side panel is primary persistent workspace. Existing InComm toolbar icon opens it directly via user gesture; automatic recognition and recording are independent of UI opening. Accessible title/status; no redundant popup, large default overlay or Home dashboard. Merchant page stays available for native validation/CAPTCHA and manual interventions. Optional small in-page status/launch control only if proven useful; non-obstructive and collapsible. Full-page extension view optional later for wide management; PWA/mobile deferred. Shared semantics/tokens, not forced identical platform layout. Four destinations are approved design candidates, subject to prototype testing:
- Queue (default): direct inline paste or explicit clipboard import, validate/deduplicate, compact summary and progress, review intended campaign/product/reward/email/terms, authorize, monitor, pause, resolve. Do not force unnecessary modal/screens.
- Rewards: verified totals and captured records, searchable redemption history as secondary view, masked credentials with deliberate reveal/copy, CSV/TSV preserving exact headers and strings. No pending reward counted as earned.
- Campaigns: merchant names, qualifying purchases, reward choices, purchase/claim deadlines, links, evidence and compatibility status, distinction between inferred/verified and stock unknown. Show slug as technical detail; distinguish current operational campaign from historical review.
- Settings: saved email, clipboard and execution preferences, appearance, storage/data management with scoped destructive confirmation, diagnostics (also linked from campaign status). Preferences never grant implicit submission authority.

## Primary journey and state semantics
Recognize automatically -> one-click workspace -> direct paste/import -> automatic validation/deduplication -> inline review -> explicit foreground authorization -> monitor -> verified capture/reconcile -> copy/export. Logical stages need not be separate screens. Remember legitimate preferences, do not re-enter known details. Import is never submission. Batch review prepares queue, not a substitute for explicit final claim authorization under existing contract.

Persistent context: active merchant/campaign, active tab connection, current transaction state, progress from verified records, relevant claim deadline. Compact inline counts rather than oversized metric cards. One context-sensitive primary action (review & start, pause, review & resume, review unresolved claim); secondary actions remain discoverable. State model: disconnected/no recognized page, unsupported/diagnostic-only, ready, importing, review, running, awaiting user (selection/CAPTCHA), paused, unresolved outcome, verified complete, confirmed error, duplicate. Status communicates what happened, what is confirmed, what remains unknown, safe next action. Timeout is not confirmed failure. Unresolved claim blocks advancement/replay; provide merchant response/email inspection and keep-unresolved options, not blind retry. Tab changes fence stale authorization. Do not obscure merchant controls. No invented success or projected amounts shown as earned.

## M3 standards
Locally packaged semantic CSS/tokens and reusable semantic components first; no mandatory framework. Palette candidate restrained blue or neutral accent; previous purple/blue mockups not binding. Original icon unchanged. System light/dark by default with overrides; semantic surfaces, text, error and success roles, no color-only state. Roboto or system font; body 14–16px, supporting text 12–14px, headings 20–24px; 4px grid, 16px default margins, moderate component-appropriate corners, M3 button variants. Minimum 48 x 48 CSS px interaction targets as project standard (stronger than WCAG minimum); normal text contrast >=4.5:1, WCAG 2.2 AA target including non-text contrast, keyboard, labels, focus visibility/unobscured focus, announcements and reduced motion. Mask credentials by default; use monospace where identifiers benefit. Responsive narrow single-column with labeled navigation, optional wider list-detail/rail if warranted. No horizontal scrolling at 320 CSS px; test 320/360/400/480px, light/dark and 200% zoom. Compact readable density, not decorative cards or excessive motion.

## Development process and gates
V0.0 parallel planning only; V0.1 synthetic prototype and state/action contract, task inventory and alternative interaction evaluation; usability review before V0.2 production UI integration. Accessibility from first implementation. Test empty, long labels, 999-item queues, duplicate/invalid, disconnected, unknown, disabled, pending/interrupted and verified states; keyboard-only tasks and screen-reader semantics, automated accessibility scan plus manual verification, responsive and visual regression. Walk through import, review, monitor, reconcile, reward reveal/copy/export, diagnostics, settings and tab switching. No feature regressions except explicitly approved safety improvements. Preserve state/preferences/rewards across navigation/interruption. Document deliberate M3 deviations and rationale. V0.5 final UX and functional acceptance, not first UX design. Prototype does not establish WCAG compliance or production compatibility.
