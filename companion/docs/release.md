# Release and rollback contract (V0.6)
 
Development packages are deterministic, versioned by manifest version and exact commit. CI uploads the ZIP, self-contained bookmarklet text/source, installation page, native checklist, build metadata and SHA-256 manifest only after tests. CI artifacts expire; they are not permanent public releases. No runtime updater, remote executable MV3 code, new host grant, destructive migration or automatic launch is introduced.

After all applicable V0.5/native/E4 and V0.6 gates pass, publish a distinct immutable version-specific release on GitHub. Intended naming: development prerelease tag `companion-v0.6.0-dev-<sha12>`; stable tag `companion-v1.0.0`. Version-specific public asset URL format: `https://github.com/dotsthewarlock/rewards/releases/download/<tag>/<asset>`. Never overwrite a released asset/tag. Use the Releases index to check availability manually; no reliance on a mutable latest URL for integrity or rollback. Stable packaging must set manifest and visible channel/version to stable only after acceptance, not just relabel this development ZIP. Stable assets must be built, tested and hashed against exact stable commit. No stable tag or asset exists yet.

Publication capability: source/ref, CI artifact download, and release metadata reads available. Current connector does not expose direct release creation/upload or Pages settings. When gates pass, use authorized least-privilege GitHub Releases publication (contents write for release job or repository owner manual upload of exact CI-verified assets). No stable Companion publication or workflow credential escalation before acceptance. The separately approved launcher-only publication below does not promote Companion to stable. Verify tag target, asset names and digest via public URL, install/update/rollback, and installation page served from version-specific asset. Keep original production tree and listener data. No release workflow automatically publishing from development pushes.
