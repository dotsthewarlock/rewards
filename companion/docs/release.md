# Release and rollback contract (V0.6)

Development packages are deterministic, versioned by manifest version and exact source commit. CI uploads the extension ZIP, self-contained bookmarklet text/source, installation page, native checklist, build metadata and SHA-256 manifest only after tests. CI artifacts expire. An architect-accepted coherent Dev checkpoint may be published unchanged as immutable version-specific GitHub Pages assets before native/live acceptance, clearly labeled testing only; this is not V1.0 or a GitHub Release. A green push alone is not promotion. No runtime updater, remote executable MV3 code, new host grant, destructive migration or automatic launch.

## D3 shared running-build identity and manual update (Companion architect proposal for Master coordination, 2026-11-27)

Reviewed baselines: [companion-dev 451d5c9](https://github.com/dotsthewarlock/rewards/commit/451d5c9d5f8242f35c8184ddbad0b5881b957d1e), [main D1 d85f088](https://github.com/dotsthewarlock/rewards/commit/d85f088b7e542ff76c57e51e8ab0098b490a4332). Existing V0.6 [candidate CI 46049375697](https://github.com/dotsthewarlock/rewards/actions/runs/46049375697) browser job 140676575871 completed successfully. Current package-development.py writes full commit/version/channel into outer build.json, but extension/index.html has a static version label and build-bookmarklet.mjs flattens that markup without exact build identity. D1 displays published semantic version and collapsed exact release suffix; it cannot detect the installed extension. This is a documentation-only coordinated proposal, not implementation, native acceptance, promotion or authority to overwrite either shared ref.

- **Identity:** one build-time immutable tuple of manifest version, internal channel and full source commit, plus distribution context (extension/bookmarklet). Derive it once from the verified package source; embed the same tuple in the local MV3 runtime and self-contained bookmarklet, and verify against outer build.json, manifest, generated URL/source and publication provenance. Build from exact clean source; unversioned/local/sandbox builds must say unverified/local, not impersonate a published build. Keep deterministic packaging, explicit allowlist and source-byte verification (except specifically generated build identity). No manual duplicated active-version constants, runtime remote code or hash self-reference. Version is human-readable; full SHA and distribution appear in collapsed version details. Frozen v15 stays byte-identical; identify it by existing pinned version/path/hash where applicable, not an invented Companion commit.
- **UX and preference:** consumer labels Regular (recommended) and Preview (testing only) map to existing internal stable/dev-development keys; never equate preference, installed/running identity or current eligible release. Shared Settings/About shows the actual running version even when disconnected; explicit Check for updates opens the permanent official distribution page. Use that page for preferred update channel, separately per distribution; remember only explicit choices in bounded page-local storage if available, otherwise session-only. Default comparison to running channel if known, otherwise Regular; mark default as such, never silently switch or install. D2 launch preference remains local to its launcher context and governs only remembered selection, with explicit Open and fresh verification. Do not imply cross-origin synchronization, silently rewrite D2 preference, or add extension storage/settings just to duplicate page preference. If Regular extension is unavailable, state so and allow explicit Preview choice; no fallback. Direct saved bookmark remains its exact build; permanent bootstrap remains unchanged and requires deliberate Open each invocation.
- **Available-release comparison:** use current verified channels.json and its immutable matching publication.json, not branch HEAD, CI artifact enumeration or a second release registry. Validate channel, exact path, hash, package metadata, full commit and short version suffix agreement; reject malformed/mismatched/unavailable provenance, fail visibly and keep last running identity unchanged. Existing stable v15 pin remains exact, no Regular extension yet. Explicit update navigation may carry only validated public distribution/version/channel/full commit in a bounded URL fragment (no merchant origin, campaign, URL, account, credential, queue, diagnostic or installation ID; no referrer). No in-workspace network update checks, no automatic transmission, no background tasks, no added permissions. Page must not claim installed-version detection; missing/older V0.6 runtime identity means manual comparison of retained package/build.json, or unknown. Match exact identities only; different SHA at same semantic version means different published build, not necessarily newer; do not infer forward/rollback order. Unavailable/invalid/offline is unknown, never up to date. A user click is required for download, launch, installation, switching or rollback; no availability check authorizes transaction execution.
- **Manual extension update/rollback:** stop with unfinished/uncertain claim; never run overlapping tools. Retain old verified version-specific archive and private backup; record current extension ID, exact package identity and sanitized data baseline. Disable (do not uninstall/remove or clear browser/site/extension data); replace complete package contents in the SAME dedicated unpacked directory, reload/re-enable explicitly, verify extension ID, exact running identity, unchanged expected permissions, preserved queue/reward/settings/diagnostic data and safe behavior. On discrepancy stop/disable, restore complete previous verified package to same folder, reload and repeat verification. A moved directory, changed ID, missing storage or unverified rollback is a failure, not a successful migration. Do not use original diagnostic listener's directory. Rollback never authorizes replay or legacy invocation while unresolved. For bookmarklet retain direct self-contained old bookmark and original v15 independent of launcher; switching only when safe and explicit, verify exact identity and saved bookmark behavior.
- **Sequence and acceptance:** Loader architect owns D2 remembered selection and D3 distribution-page/published-metadata consumption; Companion architect owns generation, shared About and adapters. Master resolves this cross-module contract, serializes shared-ref writes and publication, and synchronizes accepted launcher changes. Do not rebuild/republish immutable V0.6 just for identity labels: use existing exact candidate for consolidated native baseline when user elects; incorporate D3 into the next justified Companion package, then extend the single current native checklist with same-semver build comparison, explicit manual update and verified same-ID/data rollback between two verified eligible packages. Clarify checklist's existing disable/remove wording before update testing: removal is not safe preservation of extension-local data. Until a second genuinely useful build exists, exact two-build native update/rollback remains unverified; do not manufacture a candidate solely for the test. Stable/live E4 and monitoring remain independently gated. No new remote executable code, permissions, updater, automatic switching, promotion or transaction authority.
- **Targeted acceptance for next build:** package identity parity/determinism and no test-only runtime; About on both distributions including disconnected, correct local/unknown, safe fixed destination and keyboard/focus; explicit preference/no sync/no auto launch/download; exact match, same-semver different commit, different channel, unavailable Regular extension, invalid/missing metadata and offline/retry; no requests before user navigation or sensitive URL/referrer data; old package/launcher/v15 and all transaction invariants unchanged. Reuse existing synthetic browser/packaging/launcher CI and native checklist, no duplicate suite or approval gate. Continuous improvement: avoid a second registry, separate updater, needless cross-context preference storage, and repeated V0.6 packaging; use existing shared workspace, immutable provenance and explicit navigation. No new production scope or implementation CI claimed for this proposal.
