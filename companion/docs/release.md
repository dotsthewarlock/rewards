# Release and rollback contract (V0.6)

Development packages are deterministic, versioned by manifest version and exact source commit. CI uploads the extension ZIP, self-contained bookmarklet text/source, installation page, native checklist, build metadata and SHA-256 manifest only after tests. CI artifacts expire. An architect-accepted coherent Dev checkpoint may be published unchanged as immutable version-specific GitHub Pages assets before native/live acceptance, clearly labeled testing only; this is not V1.0 or a GitHub Release. A green push alone is not promotion. No runtime updater, remote executable MV3 code, new host grant, destructive migration or automatic launch.

## Stable release and versioned GitHub Release assets
After applicable V0.5/native/E4 and V0.6 gates and explicit stable release approval, publish distinct immutable version-specific GitHub Releases. Intended development prerelease tag companion-v0.6.0-dev-<sha12> and stable tag companion-v1.0.0; version-specific URL https://github.com/dotsthewarlock/rewards/releases/download/<tag>/<asset>. Never overwrite assets/tags. Use Releases index to check availability manually, not mutable latest for integrity/rollback. Stable manifest and visible channel/version must come from a stable build tested and hashed at exact stable commit, not a relabeled Dev ZIP. No Stable pointer change until separately accepted V1.0 and contract revision. GitHub Release assets remain outstanding. Existing connector supports source/ref, CI/artifact and release metadata, not direct release creation/upload or Pages settings; at the release gate use authorized least-privilege publication or repository-owner upload. Verify tag/asset names, hashes and public bytes plus install/update/rollback. No new backend, permission escalation before acceptance, or premature listener/data retirement. Preserve redeem/ and scan/ and original rollback.
